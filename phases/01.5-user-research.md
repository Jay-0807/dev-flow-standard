# 👥 用户研究

> 内部编号：Phase 1.5
> 模式：💬 PM 在线（PRD 之前的"用户证据底座"）

> ⚡ **快车道默认 SKIPPED**：在低风险任务（纯加法 / 内部工具 / 非面向用户的改动）下，本 phase **默认跳过**，仅在 PRD 里补一段轻量的"假设型用户画像"（1 段话：角色 / 目标 / 痛点 / 场景），并标注"基于假设，需后续验证"。
> 只有满足以下任一条件才跑完整的 3 画像流程：①中型/大型需求；②直接面向终端用户的改动；③涉及用户感知风险（错误代价高 / 信任敏感 / 合规相关）。决策写入 autonomous-decisions.md 留痕。

## 目标

在 PRD 之前，**强制用真实用户证据替代 PM 拍脑袋**。回答四个核心问题：

1. **目标用户画像**（who） — 不是抽象的"角色标签"，而是具体的人：角色 / 目标 / 痛点 / 典型工作日截面
2. **当前替代方案**（what they do now） — 用户现在用什么凑合？哪里痛？
3. **触发场景**（when & where） — 用户一天会遇到几次？在什么场景下？
4. **类似产品参考**（competitive substitutes） — 业界已有的解？为什么用户不全转过去？

**核心原则**：没有用户证据的 PRD，就是 PM 自言自语。本 phase 是"用户证据采集"的强制点。

## 触发条件

**按风险分流**：
- **低风险快车道** → 默认 SKIPPED（见顶部说明），PRD 里补 1 段假设型用户画像。
- **中型/大型 / 面向用户 / 用户感知风险** → 默认跑完整流程。仅当 PM 显式说"我已经做过用户调研，直接进 PRD"才跳过（autonomous-decisions.md 留痕）。

## 输入

- `iteration-vault/01-clarified-requirement.md`
- `<project-positioning>.md（项目自定，无则跳过）`（项目领域 / 目标用户特征，如有）
- `<project-business-context>.md（项目自定，无则跳过）`（如项目有合规要求或"用户心智隐形信息"约定，在此引用）
- （可选但强烈推荐）已有的用户访谈纪要 / 支持工单 / 产品反馈 / 使用分析数据

## 工作流（4 步）

### Step 1：跑用户场景调研

触发：调用项目可用的深度调研 skill（如 `deep-research`），场景选"用户研究"。若没有可用的调研 skill，则用一手证据替代：现有用户访谈纪要、支持工单、使用分析数据（usage analytics）、应用商店/社区评价。

前置 prompt：
```
请基于 iteration-vault/01-clarified-requirement.md 调研：
- 这个功能的目标用户画像（输出 3 个：典型 / 进阶 / 边缘）
- 目标用户在当前解决方案下的真实痛点（频次 × 强度排序）
- 业界 3 个类似产品如何处理这个问题
- 用户在这个功能上花的时间/精力的 ROI 估算
要求：每条结论必须挂证据来源（访谈/工单/使用数据/竞品调研），不允许"我推测"。
```

### Step 2：用户视角反观（站在真实使用者立场）

用调研结论 + 一手证据（访谈引语 / 工单原文 / 使用数据），站在真实使用者立场回答三个问题：
- "如果我是刚上手的新用户，这个功能对我有用吗？"
- "如果我是用了很久的资深用户，我现在用什么凑合？"
- "这个功能上线后，我什么时候/多久会用它一次？"

若项目装有领域用户角色 agent（user-research / persona-simulation 类），可让其扮演对应画像作答；否则直接基于一手证据归纳。

输出：3 条"用户真实反应"短段落，作为 PRD 写"用户故事"时的人物口吻参考。

### Step 3：画用户旅程图（mermaid 文字版）

基于 Step 1+2 输出，画两张图，PM 一眼能看懂：

**图 A：当前用户旅程**（用户现在用什么凑合解决 —— 比如手工 / 表格 / 散落的工具 / 第三方产品）
**图 B：加入新功能后的用户旅程**

用 mermaid sequenceDiagram 文字表示。关键节点标注：
- 时间消耗（"这一步要 30 分钟"）
- 情绪标签（"这一步用户最烦"）
- 错误率（"这一步用户常出错"）

### Step 4：用户心智隐形信息检查（用户没说出口的真实在意）

若项目在 `<project-business-context>.md` 里约定了"用户心智隐形"之类的合规/价值要求，先 Read 并对齐；没有则按通用问法即可。

主动追问 PM（用 AskUserQuestion 或对话）：
- 用户**没说但其实最在意**的点是什么？（举例："其实用户最怕的不是慢，是错"）
- 用户上次因这事不爽是什么场景？（具体到日期/上下文）
- 用户对自动化的真实期待是"全自动"还是"我说了算"？**（仅 AI 原生项目；非 AI 项目填 N/A 或跳过）**

把答案直接写进 `01.5-user-research.md` 的"用户心智隐形"段。这段空白 → 不允许进 Phase 2。

## autonomous 决策规则

- 若**用户群范围模糊**（PM 也说不清谁是用户）→ 标 ⚠️ + autonomous-decisions.md 记录 + 继续，但 Phase 2 PRD 阶段必须由 PM 补充
- 若用户视角反观（Step 2）**强烈质疑**"这个需求其实不是用户要的" → 写入 ESCALATION 候选 + 提醒 PM 重新评估（不直接触发 R 红线，但 PRD 关卡时 PM 会看到）
- 若调研 skill 调用失败 / 不可用 → 降级为"仅一手证据（访谈/工单/使用数据）+ Step 4 反问"，明确标记降级

## 与其他 phase 的接口

- **上游**：Phase 1 输出的 01-clarified-requirement.md
- **下游**：Phase 2 PRD 必须显性引用本 phase 的"必做功能 ranking"和"用户感知细节"
- **后续追溯**：Phase 12.5 ⛳ 早晨复盘时，验收对象（真实用户）的画像必须与本 phase Section 1 中的 3 个画像至少匹配 1 个

## 失败回退

- **完全没有访谈/工单数据可参考** → 切到"假设型用户研究"模式：所有结论标"基于推测，需要后续验证"，并在 Phase 12.5 ⛳ 早晨复盘时**强制做真实用户验证**（不允许跳过）
- **PM 拒绝回答 Step 4（用户心智隐形）问题** → 暂停 phase，明确告知 PM"用户心智隐形信息缺失会让 PRD 失真，请补充"
- **调研跑出来全是泛泛而谈** → 重试一次，前置 prompt 加更具体的场景约束（具体角色 / 使用规模 / 关键约束量纲，由项目领域决定）

## 维护备忘

- 每装一个新的"用户研究"类 skill（如未来引入 user-interview 工具）→ 更新 Step 1/2 的调用清单
- 每次跑完一次，把"哪类用户在这个 phase 容易卡住"经验沉淀到本文件末尾

# 👥 用户研究

> 内部编号：Phase 1.5
> 模式：💬 PM 在线（PRD 之前的"用户证据底座"）

## 目标

在 PRD 之前，**强制用真实用户证据替代 PM 拍脑袋**。回答四个核心问题：

1. **真实用户画像**（who） — 不是"店主/客服"角色标签，是有名字、有店铺规模、有 GMV、有典型工作日的人
2. **当前替代方案**（what they do now） — 用户现在用什么凑合？哪里痛？
3. **触发场景**（when & where） — 用户一天会遇到几次？在什么场景下？
4. **类似产品参考**（competitive substitutes） — 业界已有的解？为什么用户不全转过去？

**核心原则**：没有用户证据的 PRD，就是 PM 自言自语。本 phase 是"用户证据采集"的强制点。

## 触发条件

**默认跑**。仅当 PM 在 Phase 1 末尾显式说"我已经做过用户调研，直接进 PRD"才跳过（autonomous-decisions.md 留痕）。

## 输入

- `iteration-vault/01-clarified-requirement.md`
- `<project-positioning>.md（项目自定，无则跳过）`（业务特征（如有））
- `<project-business-context>.md（universal 版无 项目业务哲学（如有），可由项目自定）`（**重点**：第 4 维度"用户心智隐形"）
- （可选但强烈推荐）已有的客户访谈纪要 / 客服工单 / 产品反馈

## 工作流（4 步）

### Step 1：调 firefly-deep-research-skill 跑用户场景调研

触发：Agent 工具调用 `firefly-deep-research-skill`，场景选"用户研究"（8 大场景之一）。

前置 prompt：
```
请基于 iteration-vault/01-clarified-requirement.md 调研：
- 这个功能的目标用户画像（输出 3 个：典型 / 进阶 / 边缘）
- 目标用户在当前解决方案下的真实痛点（频次 × 强度排序）
- 业界 3 个类似产品如何处理这个问题
- 用户在这个功能上花的时间/精力的 ROI 估算
要求：每条结论必须挂证据来源（访谈/工单/竞品调研），不允许"我推测"。
```

### Step 2：调 marketing agent 做"店主视角"反观

**国内电商需求** → 调 `marketing-china-ecommerce-operator`
**跨境电商需求** → 调 `marketing-cross-border-ecommerce`

让 agent 扮演真实店主，回答三个问题：
- "如果我是 2 个月新店店主，这个功能对我有用吗？"
- "如果我是 3 年老店店主，我现在用什么凑合？"
- "这个功能上线后，我什么时候/多久会用它一次？"

输出：3 条"店主真实反应"短段落，作为 PRD 写"用户故事"时的人物口吻参考。

### Step 3：画用户旅程图（mermaid 文字版）

基于 Step 1+2 输出，画两张图，PM 一眼能看懂：

**图 A：当前用户旅程**（用户怎么用 Excel/手工/微信群凑合解决）
**图 B：加入新功能后的用户旅程**

用 mermaid sequenceDiagram 文字表示。关键节点标注：
- 时间消耗（"这一步要 30 分钟"）
- 情绪标签（"这一步用户最烦"）
- 错误率（"这一步用户常出错"）

### Step 4：r4 第 4 维度检查（用户心智隐形）

Read `<project-business-context>.md（universal 版无 项目业务哲学（如有），可由项目自定）` 中"用户心智隐形"维度。

主动追问 PM（用 AskUserQuestion 或对话）：
- 用户**没说但其实最在意**的点是什么？（举例："其实店主最怕的不是慢，是错")
- 用户上次因这事不爽是什么场景？（具体到日期/上下文）
- 用户对 AI 的真实期待是"全自动"还是"我说了算"？

把答案直接写进 `01.5-user-research.md` 的"用户心智隐形"段。这段空白 → 不允许进 Phase 2。

## autonomous 决策规则

- 若**用户群范围模糊**（PM 也说不清谁是用户）→ 标 ⚠️ + autonomous-decisions.md 记录 + 继续，但 Phase 2 PRD 阶段必须由 PM 补充
- 若 marketing agent **强烈质疑**"这个需求其实不是用户要的" → 写入 ESCALATION 候选 + 提醒 PM 重新评估（不直接触发 R 红线，但 PRD 关卡时 PM 会看到）
- 若 firefly-deep-research-skill 调用失败 / 不可用 → 降级为"仅 marketing agent + Step 4 反问"，明确标记降级

## 与其他 phase 的接口

- **上游**：Phase 1 输出的 01-clarified-requirement.md
- **下游**：Phase 2 PRD 必须显性引用本 phase 的"必做功能 ranking"和"用户感知细节"
- **后续追溯**：Phase 12.5 ⛳ 早晨复盘时，验收对象（真实用户）的画像必须与本 phase Section 1 中的 3 个画像至少匹配 1 个

## 失败回退

- **完全没有访谈/工单数据可参考** → 切到"假设型用户研究"模式：所有结论标"基于推测，需要后续验证"，并在 Phase 12.5 ⛳ 早晨复盘时**强制做真实用户验证**（不允许跳过）
- **PM 拒绝回答 r4 第 4 维问题**（Step 4） → 暂停 phase，明确告知 PM"用户心智隐形信息缺失会让 PRD 失真，请补充"
- **deep-research 跑出来全是泛泛而谈** → 重试一次，前置 prompt 加更具体的电商场景约束（金额范围 / 类目 / 店铺规模）

## 维护备忘

- 每装一个新的"用户研究"类 skill（如未来引入 user-interview 工具）→ 更新 Step 1/2 的调用清单
- 每次跑完一次，把"哪类 目标客户在这个 phase 容易卡住"经验沉淀到本文件末尾

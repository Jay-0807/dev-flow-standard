# Phase 12.5 — 早晨复盘 ⛳ PM 关卡 2（v4 新增）

## 这是什么

夜间模式跑完后的 PM 验收关卡。PM 不需要看代码，跟着 4 步结构化清单走完，给出 4 选项之一：

- ✅ merge Release PR（直接发版）
- 🔄 局部 redo（指定某 phase 或某决策回退）
- ❌ 整体重做（丢弃跑完的结果回 Phase 2）
- ⏸ 推到下个夜晚继续

---

## 触发方式

两种：

### 自动触发
Phase 12 完成时 skill 检测 `state.yaml` 的 `mode=morning-review-pending` → 自动进 12.5。

### 手动触发
PM 输入以下任一短语：
- `/morning`
- `早上好`
- `复盘`
- `我回来了`
- `夜间跑完了吗`

skill 查 `state.yaml`：
- 若 mode=morning-review-pending → 进入 12.5
- 若 mode=night-mode（还在跑）→ 提醒 PM "夜间模式还在跑，等跑完"
- 若 mode=escalated → 直接进入 escalation 处理（不是 12.5）

## 工作流（4 步固定模板）

### Step 1：先给 PM 30 秒摘要

显示在终端，3-5 行中文：

```
🌅 早上好！夜间模式已跑完。

✅ 总体状态：成功
📊 摘要：完成 [N]/[M] 任务 | 自治决策 [K] 条（⚠️ [X] 条）| 用户验收 [Y.Y]/5

进入早晨复盘流程 (Phase 12.5)，4 点关注点：
  [1/4] ⚠️ 自治决策审计（[X] 条值得你看）
  [2/4] 📝 审查报告 should-fix（[A] 项建议）
  [3/4] 👥 用户验收（最痛：[一句话]）
  [4/4] 🔍 Karpathy 4 原则违规扫描（[B] 项）

按 Enter 进入 [1/4]，或输入 "skip" 跳到选项。
```

### Step 2：跑 4 点关键复盘清单（顺序固定）

按下列顺序，每点 skill 先输出"摘要+提示"，然后说"看完点[继续]"：

#### 关注点 1：⚠️ 标记的自治决策

skill 自动 grep `autonomous-decisions.md` 里所有 ⚠️ 标记，用 markdown 表格列出：

| 决策 ID | Phase | 触发情境 | 选择 | PM 关注理由 | checkpoint |
|---|---|---|---|---|---|
| #7 | 4 | vendor 选型 | lib-A vs lib-B 选了 A | 与现有栈兼容性 | ✅ ckpt-decision-7 |

每条决策附"📍跳转：vault/checkpoints/ckpt-decision-N/"链接（C 节决策回放接口）。

PM 视角问句：**「这些自治选择你看完后觉得 OK 吗？」**

#### 关注点 2：审查报告的 should-fix 项

skill 从 `iteration-vault/09-review-reports/summary.md` 提取所有 should-fix（不阻塞但建议修）：

| 项 | 严重度 | 位置 | 是否进 backlog |
|---|---|---|---|
| API 错误处理可统一 | 🟡 major | src/api/users.ts | ? |
| 弃用日志可清理 | 🟢 minor | src/lib/legacy/ | ? |

PM 视角问句：**「这些建议要不要本次顺手修？还是进 backlog？」**

#### 关注点 3：用户验收结果（10.5）

- 评分：[X.Y]/5
- 用户反馈聚类（前 3）：
  - [反馈 1]（[N] 人提）
  - [反馈 2]（[M] 人提）
- 最爱：[摘录]
- **最痛**：[摘录]（高亮）

PM 视角问句：**「真实用户的反馈你接受吗？」**

#### 关注点 4：Karpathy 4 原则违规扫描

skill 自动扫 `autonomous-decisions.md` + `07-implementation-log.md` + `<phase>-gan/scorecard.md`，找以下 pattern：

| 原则 | 违规类型 | 数量 | 例子 |
|---|---|---|---|
| Think | 假设没浮现 | [N] | autonomous-decisions.md L42: ... |
| Simplicity | 过度抽象 | [M] | 08-tech-debt-audit.md L15: ... |
| Surgical | 无关改动 | [K] | 09-review-reports/adversarial.md: ... |
| Goal | 未达 AC 但 claim done | [L] | 10-verification-report.md: ... |

PM 视角问句：**「这些技术质量问题你能接受吗？」**

### Step 3：AskUserQuestion 4 选项

```
question: "夜间模式跑完了，4 点关键复盘看过了。下一步？"
header: "早晨复盘 — 关卡 2"
options:
  - label: "✅ merge Release PR，发版"
    description: "我看过 4 点都 OK，直接发版（skill 会调 gh pr merge）"
  - label: "🔄 局部 redo（指定某 phase 或某决策回退）"
    description: "大方向 OK，但有某段要重做 — 我会指出具体哪段"
  - label: "❌ 整体重做"
    description: "本次方向不对，丢弃跑完的结果，回 Phase 2 重写 PRD"
  - label: "⏸ 推到下个夜晚继续"
    description: "今天没空决定，明早再说 — vault 保留原状不动"
```

### Step 4：根据 PM 选择分流

| 选项 | 后续动作 |
|---|---|
| ✅ merge | 调 `gh pr merge <release-pr> --auto` + 归档 vault → `history/<timestamp>-<feature>/` + state.yaml mode=done + skill 退出 |
| 🔄 局部 redo | 进入 §3.1 局部 redo 子流程 |
| ❌ 整体 redo | 提示 PM "你确认丢弃本次产出吗？" 二次确认后，归档 vault 到 `history/REJECTED-<timestamp>/`，回 Phase 2 |
| ⏸ 推下夜 | 写 `state.yaml: mode=postponed`，`morning_review_postponed_until: <next-morning>`, skill 退出但不归档，下次 PM 回话再进 12.5 |

## 3.1 局部 redo 子流程（Step 4 选 🔄 时）

PM 选 🔄 → skill 问："你想 redo 哪段？" 给三类选项：

### A. 某个 phase 重做（Phase 2.5-12 任选）

例：「Phase 5a UX 重做，因为线框不对」

→ skill 把 vault 状态回滚到对应 phase 开始前的 checkpoint（见 `decision-replay.md`）
→ 标记 `state.yaml: mode=night-mode, current_phase=5a-redo`
→ 进入夜间模式 batch redo 重跑该 phase 起的下游

### B. 某条自治决策回退（autonomous-decisions.md 里的 #N 条）

例：「决策 #7 选了 deprecate，我想改成直接删」

→ 用 `decision-replay.md` 机制：恢复到决策 #7 前的 vault 状态 + 注入新方向
→ 进入夜间模式 batch redo 重跑

### C. backlog 增项（不重做，只把 should-fix 项加入下次 sprint）

→ 写到 `iteration-vault/backlog.md`
→ 回到 Step 4 重新让 PM 选 ✅/⏸/❌

## 边界情况

### PM 离线超长（≥ 3 天）

- vault 保留，`state.yaml` 标 `morning_review_pending_since: <date>`
- 下次 PM 回话仍直接进 12.5（vault 不过期，但展示"待复盘 N 天"提醒）
- 超 7 天：autonomous-decisions.md 末尾写 ⚠️ "vault 7+ 天未复盘，建议先重新跑校验依赖未漂移"
- 超 30 天：强烈建议丢弃 vault 重跑

### 决策回放后跑出更差结果

PM 选 🔄 redo decision #N → batch redo 跑完 → 12.5 第二次复盘 → 评分变差：

skill 主动提示：「本次 redo 评分低于原版（X.X → Y.Y）。建议：
- ✅ 接受 redo 结果
- 🔙 回退到 redo 前的 vault（用 `history/<timestamp>-pre-redo/`）
- 🔄 再次 redo（最多 3 次连续 redo，超出强制 ❌ 整体 redo）」

### 关注点的某一份输入文件缺失

如没跑 10.5 → 关注点 3 标"未做用户验收"，不阻塞，但在最终决策选项前显性提示。

**v4 决策**：保留 Phase 12 末尾的"🌅 夜间模式跑完"摘要段（作为"摘要预览"），但**移除其中的"PM 一键决策动作"**，全部决策动作迁移到 Phase 12.5 的 AskUserQuestion。

等价于：
- Phase 12 = "递交报告"
- Phase 12.5 = "PM 审阅+签字"

## 失败回退

- PM 拒绝跑 12.5 复盘（直接说"merge"）→ skill 仍要走一遍 Step 1-2 摘要，PM 看过后才能跳到 Step 4 ✅ 选项
- 4 点关注点的某一份输入文件缺失 → 标"未做"在该关注点，不阻塞，但在最终决策选项前显性提示
- PM 离线 → vault 保留，state.yaml 标 morning_review_pending，下次回话重入

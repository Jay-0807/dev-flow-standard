# 🔄 文档代码漂移检测

> 内部编号：Phase 11.5  |  独立命令：/u-sync
> 模式：🤖 Autonomous（5 维度漂移检测，学 autodev-sync）
> 5 维度：tech stack / API endpoints / data models / page routes / core deps
> 三级警报：INFO / WARN / ERROR（ERROR 级阻塞 Phase 12）

## 这是什么

Phase 11 Release notes 写完后、Phase 12 git release 前的**必跑短 phase**。学 autodev-sync 的"扫代码 + git history → 更新设计文档状态标记 + 5 维度漂移检测"。

**核心目的**：防止"文档说 A 但代码做 B"的长期累积。每次发布前强制扫一遍。

---

## 目标

输出 `iteration-vault/11.5-sync-report.md`，含：
1. 设计文档中每条任务/接口的状态标记（`[ ]` 未做 / `[~]` 进行中 / `[x]` 已完成）
2. 5 维度漂移检测三级警报（INFO / WARN / ERROR）
3. **ERROR 级阻塞 Phase 12 发布**

---

## 触发条件

每次都跑（无开关）。Phase 11 完成后自动进入本 phase。

---

## 输入

- 全部代码（git workspace）
- git history（最近 100 commits）
- `iteration-vault/02-PRD.md`
- `iteration-vault/04-architecture.md`
- `iteration-vault/04.5-api-design.md` + `04.5-api-spec.yaml`

## 工作流（2 步）

### Step 1：状态标记更新（autodev-sync 风格）

扫代码 + git history 判定每条任务/接口的当前状态：

**判定规则**（严格，autodev 实证有效）：
- `[x]` 已完成：代码存在 + 单测通过 + 真实调用链
- `[~]` 进行中：代码存在但缺单测 OR 部分实现
- `[ ]` 未开始：
  - 代码不存在
  - 代码存在但**空函数体 / NotImplementedError / 桩代码**
  - 代码存在但**数据源是 mock / fake**
  - 代码存在但**未被任何上游调用**（dead code）

**关键约束**（autodev 反模式）：
- ❌ 空函数 + 看起来对的注释 = `[ ]` 不是 `[~]`
- ❌ Mock 数据驱动 = `[ ]` 不是 `[x]`
- ❌ 调用链断（API 写了但前端不调）= `[ ]` 不是 `[x]`

更新这些文件**原地状态标记**：
- `06-task-breakdown.md` 每个 task 的 status 字段
- `04.5-api-design.md` 每个 endpoint 的实现状态
- `05b-ui-spec.md` 每个组件的实现状态

### Step 2：5 维度漂移检测

| 维度 | 检测方法 | INFO / WARN / ERROR 阈值 |
|---|---|---|
| **技术栈漂移** | 比对 `package.json` vs `design.md` 标的版本 | major 版本不一致 = ERROR；minor 不一致 = WARN；patch 不一致 = INFO |
| **API endpoint 漂移** | 比对 `04.5-api-spec.yaml` vs 实际代码 router | 删除已发布 endpoint = ERROR；签名变化 = WARN；新增不影响既有 = INFO |
| **数据模型漂移** | 比对 `prisma/schema.prisma` vs `04-architecture.md §3` | 删除已发布字段 = ERROR；类型变化 = WARN；新增 = INFO |
| **页面路由漂移** | 比对 `app/` 或 `pages/` 实际路由 vs `05a-ux-design.md §3` | 删除页面 = ERROR；路径变化 = WARN；新增 = INFO |
| **核心依赖漂移** | 比对 import 关系 vs `04-architecture.md §1 数据流` | 新增跨边界依赖 = WARN；删除关键依赖 = ERROR |

## 三级警报

### INFO
- 小差异，自动同步文档
- 不阻塞 Phase 12
- 写到 `11.5-sync-report.md` "信息变更"段

### WARN
- 中等差异，PM 在 Phase 12.5 看
- 不阻塞 Phase 12 但建议处理
- 写到 `11.5-sync-report.md` "警告"段
- autonomous-decisions.md 标 ⚠️

### ERROR
- 重大漂移（删除已发布的 API / 字段 / 页面）
- **阻塞 Phase 12 发布**
- 触发 R4 红线（要删除既有功能）→ 升级 PM
- 写 `ESCALATION-R4-drift.md`

## 对 PM 的摘要

```
Phase 11.5 漂移检测完成:
- 任务状态更新: [N] 个标 [x] / [M] 个标 [~] / [K] 个标 [ ]
- 漂移检测:
  - INFO: [X] 项（已自动同步文档）
  - WARN: [Y] 项（PM 在 12.5 看）
  - ERROR: [Z] 项（阻塞 Phase 12，触发 R4）

如 ERROR > 0 → 升级 PM 决策
如仅 INFO/WARN → 继续 Phase 12
```

---

## 🤖 Autonomous 决策规则

- ERROR 漂移 → 强制 R4 升级（即使是 1 项）
- WARN 漂移 → 记 autonomous-decisions.md ⚠️ + 继续
- INFO 漂移 → 自动同步文档（updated_at + diff 备注）+ 继续
- 状态标记冲突（task 标 [x] 但代码缺）→ 强制改回 [ ] + WARN

## 失败回退

| 失败 | 兜底 |
|---|---|
| 设计文档某文件不存在 | 跳过该维度的漂移检测 + 标 INFO |
| 状态标记更新失败（read-only file system 等）| 写 `iteration-vault/SYNC_ERROR.md` + 跳过更新但继续检测 |
| 跑漂移检测超时（> 10min）| 用已有结果 + 标 WARN "检测不完整" |

---

## autodev-sync 反模式（必拒绝）

- ❌ 把 `[~]` 标在"代码存在但桩代码"任务（应标 `[ ]`）
- ❌ 把 `[x]` 标在"代码存在但 mock 数据"任务（应标 `[ ]`）
- ❌ 漂移检测仅看代码 / 仅看文档（必须双向比对）
- ❌ ERROR 级漂移当 WARN 处理（必须阻塞 + 升级）

---

## Standalone 模式

可独立触发：`/u-sync`
不依赖主流水线，对当前工作目录跑 5 维度漂移检测（代码 vs 设计文档）。

5 维度：
- tech stack（package.json/pyproject.toml vs design）
- API endpoints（OpenAPI vs 实际路由）
- data models（DB schema vs 设计）
- page routes（前端路由 vs 设计）
- core deps（核心依赖版本）

输出：单跑模式写 `.u-sync-report-<timestamp>.md` 到当前目录。
三级警报：INFO / WARN / ERROR
ERROR 级 → 同时写 DEBUG-TRACE.md（独立模式不阻塞，仅记录）。

# 💡 方案发散

> 内部编号：Phase 2.5
> 模式：🤖 Autonomous + GAN（v4 新增，学 autodev-brainstorm）
> 工作流：DIVERGE 3-5 方案 → EVALUATE 4 维 → CONVERGE 选最优

## 这是什么

PRD 通过后、Phase 3 影响面 + Phase 4 架构前，强制走 **DIVERGE → EVALUATE → CONVERGE** 三步：

1. **DIVERGE**: 生成 3-5 个**架构层真正差异**的方案（反"方案只差框架名"反模式）
2. **EVALUATE**: 四维评分矩阵（需求覆盖 / 可行性 / 长期维护 / 调研对齐）
3. **CONVERGE**: 最高分方案进入 Phase 3 ADR；写明被否方案理由

**核心约束**："**Options differ only in framework names**" 是反模式 → 强制架构层差异（如：单体 vs 微服务 vs serverless；BFF vs GraphQL gateway；CRDT vs operational transform）。

---

## 目标

避免"PRD 直接跳 ADR"导致的伪二选一（"用 React 还是 Vue"——这种问题不是真的二选一，React 就够了）。本 phase 强迫"真的考虑过多个架构方向"。

---

## 触发条件

每次都跑（无开关）。即使是小迭代，也要走一遍（3-5 分钟即可）。

---

## 输入

- `iteration-vault/02-PRD.md`
- `iteration-vault/01.5-user-research.md`（用于 EVALUATE 调研对齐维度）
- `<project-business-context>.md（universal 版无 项目业务哲学（如有），可由项目自定）`（1-3 维保留）
- `<project-positioning>.md（项目自定，无则跳过）`
- `principles/karpathy-llm-coding.md`
- `templates/brainstorm-matrix.md`

## 工作流（3 步）

### Step 1：DIVERGE ✅ 跑 GAN

**GAN 钩子**：
- 任务类型：`brainstorm-diverge`
- 输入：02-PRD.md + 01.5-user-research.md + 反模式说明
- 输出路径：`iteration-vault/02.5-brainstorm-diverge-gan/`
- 默认 N=5（含早退）
- reviewer 重点检查：是否真有 3-5 个架构层差异方案

**Generator 任务**：
- 生成 3-5 个**架构层真正差异**的方案
- 每个方案标：核心思路 / 关键依赖 / 关键风险 / 预估工时（粗略）

**反模式（reviewer 必拒）**：
- ❌ 方案 1 用 React + 方案 2 用 Vue（只差框架名）
- ❌ 方案 1 用 Postgres + 方案 2 用 MySQL（差异不在架构层）
- ❌ 给 5 个但其实只有 2 个真正不同（其余是变体）

**合格示例**（电商定价系统）：
- 方案 A: 实时 LLM 计算（每次请求调 LLM）
- 方案 B: 预计算 + 缓存（cron 跑批，存 Redis）
- 方案 C: 规则引擎（业务规则驱动，不用 LLM）
- 方案 D: 混合（核心走 LLM + 边缘走规则）

**输出**：`iteration-vault/02.5-brainstorm-diverge.md`（用 `templates/brainstorm-matrix.md` §1）

### Step 2：EVALUATE（不跑 GAN — 机械评分）

对每个方案，按 4 维打分（1-5）：

| 维度 | 评分依据 |
|---|---|
| 需求覆盖度 | PRD 的 AC 覆盖比例 |
| 技术可行性 | 现有技术栈匹配度 + 实施风险 |
| 长期维护成本 | 5 年视角，运维复杂度 + 演进灵活性 |
| **调研对齐度** | 与 Phase 1.5 用户研究的对齐（关键！）|

**调研对齐度**特别重要——autodev 强约束：方案必须扎根用户研究，不是"工程师觉得酷"。

输出 4×N 矩阵（N = 候选方案数）。

### Step 3：CONVERGE ✅ 跑 GAN

**GAN 钩子**：
- 任务类型：`brainstorm-converge`
- 输入：上两步输出 + 评分矩阵
- 输出路径：`iteration-vault/02.5-brainstorm-converge-gan/`
- 默认 N=5（含早退）
- reviewer 重点检查：选择理由是否站得住 + 否决方案理由是否明确

**Generator 任务**：
- 选最高分方案（总分相同则按"调研对齐度"加权）
- 详写选择理由（≥ 3 条具体）
- 详写每个被否方案的否决理由（≥ 1 条具体，避免"看着不行"）

**输出**：`iteration-vault/02.5-brainstorm-converge.md`（用 `templates/brainstorm-matrix.md` §2-§3）

## 对 PM 的摘要

```
Phase 2.5 完成：
- 发散 [N] 个方案
- 评分最高: 方案 [X]（总分 [Y]/20）
- 选这个的关键理由: [一句话]
- 主要被否方案: [简短列表 + 理由]
```

PM 一般不看（autonomous），但 Phase 12.5 复盘时可在"⚠️ 决策审计"看到本 phase 决策。

---

## 🤖 Autonomous 决策规则

- 同分时按"调研对齐度"加权（这维度优先）
- 仍同分 → 选最简单方案（Karpathy Simplicity First）
- GAN reviewer 反复说"方案差异不够"（>2 次）→ 标 ⚠️ 决策 + 选当前 Top 1 + 留 Phase 12.5 PM 看

---

## 与其他 phase 的接口

**上游**：Phase 2 PRD（必通过）

**下游**：
- Phase 3 影响面：基于选定方案分析影响
- Phase 4 架构：选定方案作为 ADR 起点
- Phase 12.5 早晨复盘：被否方案在"⚠️ 决策审计"段（PM 可质疑）

## 失败回退

| 失败 | 兜底 |
|---|---|
| Generator 5 轮都给不出 3 个真差异方案 | 用最后一轮版本 + 标 needs_improvement + Phase 12.5 PM 看 |
| EVALUATE 矩阵全维度相同 | autonomous-decisions.md 标 ⚠️ + 选 Top 1 + Phase 12.5 PM 看 |
| CONVERGE GAN 5 轮无 PASS | 用最高分版本作 final + needs_improvement |

---

## autodev-brainstorm 反模式（必拒，写入 reviewer prompt）

- ❌ Options differ only in framework names（最常见反模式）
- ❌ 多个方案其实是同一思路的微变体
- ❌ 选择理由含"我感觉" / "看起来更好"（必须具体技术或业务理由）
- ❌ 否决理由仅 "另一个更好"（必须说被否的具体问题）
- ❌ 不引用 PRD AC（方案得跟用户需求绑定）
- ❌ 不引用 Phase 1.5 用户研究（调研对齐度不能空）

## 维护备忘

- 每次跑出"方案数少 < 3" → 调 generator prompt 加强 DIVERGE 引导
- 每次 PM 在 12.5 推翻选择 → 复盘是 EVALUATE 维度有问题还是 CONVERGE 推理有问题
- 调研对齐度权重（v4 = 与其他维度平等）4 周后视情况升权

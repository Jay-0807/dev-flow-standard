# 📚 设计压缩成开发地图

> 内部编号：Phase 5.9  |  独立命令：/u-compress
> 模式：🤖 Autonomous（v4 新增，学 autodev-compress）
> 产出：INDEX.md (<100 行) + RULES.md (<80 行)，实施 phase 强制读这两份不读全量

## 这是什么

Phase 5 §2 UI Spec 完成后、Phase 6 任务分解前的**短 phase**。把厚设计文档（PRD + 架构 + API + UI + UX）压缩成两份"地图"，供 Phase 6+ 使用：

- `iteration-vault/INDEX.md`（< 100 行）：知识地图（"信息在哪里"，不是摘要）
- `iteration-vault/RULES.md`（< 80 行）：硬约束（版本/命名/质量红线/禁用模式）

**核心哲学**："**地图不是摘要**"——保留索引而非剥离细节。Phase 6 / 7 / 8 / 9 实施 phase **强制加载这两个文件而非全量原始文档**，token 节省 ~70%。

---

## 目标

PM 不要看本 phase 产出（INDEX/RULES 是给后续 phase 的 LLM 看的）。但 PM 可在 12.5 复盘时打开验证质量。

---

## 触发条件

每次都跑（无开关）。即使本迭代仅修 bug，也需重生成 INDEX/RULES 防止漂移。

- `iteration-vault/02-PRD.md`
- `iteration-vault/02.5-brainstorm-converge.md`
- `iteration-vault/04-architecture.md`

## 工作流（3 步，不跑 GAN — 机械压缩）

### Step 1：扫描全部设计文档

按"信息位置"分类（不要摘要内容）：

- 哪个文件 / 哪个段含什么类型的信息
- 例：业务规则 → 02-PRD.md 第 5 节 + 04-architecture.md 第 2 节

### Step 2：生成 INDEX.md（< 100 行）

按 `templates/index-template.md` 写：

```markdown
# Iteration INDEX (Knowledge Map)

## 项目概述（1-2 句）
<feature-name>: <一句话>

## 技术栈（一行）
<项目技术栈，例：Next.js + Postgres>

## 知识地图

| 类型 | 位置 | 行号 |
|---|---|---|
| 用户故事 | 02-PRD.md §4 | L42-78 |
| 业务规则 | 02-PRD.md §5 + 04-architecture.md §2 | ... |
| API endpoints | 04-architecture-and-api.md §1 | L20-150 |
| 数据 schema | 04-architecture.md §3 | L80-120 |
| UI 页面 | 05-interface-design.md §1 UX + §2 UI Spec | ... |
| 用户旅程 | 01.5-user-research.md §3 + 05-interface-design.md §1 | ... |
| AC 列表 | 02-PRD.md §6 | L100-180 |
| 风险 | 02-PRD.md §9 | ... |
| 自治决策 | autonomous-decisions.md（持续追加）| ... |
| GAN trace | <phase>-gan/trace.md（按 phase 查）| ... |

## 核心约束（3-5 条）

1. r4 哲学 1-3 维必落实（confidence / human_review / data_source）
2. 项目业务协议（如有）信封 9 字段强制
3. RFC 9457 错误格式
4. 7 Quality Redlines（详见 RULES.md）

## 本次迭代特殊点

- 涉及 <N> 个新 API（详见 04-architecture-and-api.md）
- 涉及 <M> 个 UI 页面（详见 05-interface-design.md）
- Phase 6 估算 <X> 个 code task（<Y> 含前端）

---

**生成于**: <YYYY-MM-DD HH:mm>
**文件数**: <N>
**总行数**: <X>
```

### Step 3：生成 RULES.md（< 80 行）

按 `templates/rules-template.md` 写：

```markdown
# Iteration RULES (Hard Constraints)

> 本文件是本迭代的硬约束。所有 Phase 6/7/8/9 实施 phase 必读。

## 1. 框架 & 依赖版本

- Next.js: 14.x
- Prisma: 5.x
- TypeScript: 5.x
- Tailwind: 3.x
- [其他关键依赖]

## 2. 命名约定

- 文件: kebab-case (`user-orders.tsx`)
- 组件: PascalCase (`UserOrders`)
- 函数: camelCase (`getUserOrders`)
- DB 表/字段: snake_case (`user_orders`, `created_at`)
- 项目业务消息: dot.notation (`order.cancel`)

## 3. API 鉴权 / 响应标准

- 用户 → 后端: Bearer JWT
- agent → agent: mTLS + signed envelope
- 错误格式: RFC 9457 Problem Details
- 限流: 100 req/min per-user

## 4. 7 Quality Redlines（详见 gan-engine/quality-redlines.md）

- R1: 禁占位符（TODO/FIXME/stub）
- R2: 禁 mock 替代
- R3: 禁降级语言（"暂时"/"先用"）
- R4: 禁过时技术
- R5: OSS 复用优先
- R6: 前端 icon 系统（no emoji as UI icon）
- R7: 禁未验证环境断言

## 5. 禁用模式

- ❌ 直接删 API 接口（必须 deprecate）
- ❌ LLM 输出 API 没 confidence
- ❌ 业务规则硬编码进代码
- ❌ 跨业务边界共享 DB 表
- ❌ 默认展示全部信息（autodev-ui 反模式）

## 6. 本次迭代特殊约束

- <如有，从 PRD / 架构提取>
- <例：本次涉及业务协议升级，所有业务 endpoint 用 v2>

---

**生成于**: <YYYY-MM-DD HH:mm>
```

## 🤖 Autonomous 决策规则

- 行数超过上限 → 自动 trim 次要信息（保留核心约束）
- 关键信息没法压缩 → 在 INDEX 加链接到原文件而非内联

---

## 与其他 phase 的接口

**上游**：所有 Phase 2-5 输出

**下游 - 强制约束**：
- Phase 6 任务分解：必读 INDEX + RULES，不读全量设计文档
- Phase 7 实施：每个 code task spawn 的 agent prompt 必含 INDEX + RULES（不读全量）
- Phase 8 代码债：审查时对照 RULES
- Phase 9 三路审查：reviewer prompt 必含 RULES

---

## 失败回退

| 失败 | 兜底 |
|---|---|
| 上游某文件不存在 | 跳过该文件，标"未生成"在 INDEX 对应位置 |
| INDEX 超 100 行 | 自动 trim "本次迭代特殊点"段先 |
| RULES 超 80 行 | 自动 trim "本次迭代特殊约束"段先 |
| 全部上游文件缺 | 写 `iteration-vault/COMPRESS-ERROR.md`，标 R3 升级 |

## Standalone 模式

可独立触发：`/u-compress`
不依赖主流水线，对当前 iteration-vault/（或指定路径）跑压缩。
输入：现有 04-architecture-and-api.md + 05-interface-design.md + 02-PRD.md 等
输出：INDEX.md + RULES.md 到同目录或当前目录。
适合：把别人写的厚设计文档压成开发可消费的精简版。

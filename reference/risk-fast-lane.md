# 风险分级快车道 — 按 SIZE 定深度，按 RISK 定是否保留 GAN/红线

> **为什么有这个文件**：实证 bake-off（对比 autodev）发现两件事——
> 1. 对中小任务，17 phase 的**外围 ceremony（用户研究 3 画像 / 方案发散 / ADR / 厚 PRD+docx / 2 个 PM 关卡）是空转**，甚至产出更 buggy（多花文档没换来更对的代码）。
> 2. 但**对抗式 GAN 是承重墙**：它在交付前抓出了自写单测漏掉的真金钱 bug。而"碰钱/认证/并发"的任务**看着小、藏着坑**（一个单文件番茄钟和一个单文件分账工具体量相同，风险天差地别）。
>
> **结论（本 skill 的核心路由原则）**：
> - **深度按 SIZE 走** —— 小任务砍掉外围文档与关卡。
> - **GAN/红线按 RISK 走** —— 命中风险面就**绝不关 GAN**，哪怕任务再小。
> - 最危险的反模式：把 GAN 当成"大任务才跑的重型流程"按 SIZE 关掉 —— 小而危险的任务正是丢了 GAN 最致命的地方。

---

## Step 0 自动分级（不打扰 PM）

启动时对需求做两个**正交**判定，写入 `00-intake.md` 顶部：

```
Size: XS | S | M | L
Risk: ✅命中风险面 | ⚪无 （命中清单：<列出关键词>）
Lane: 🏃 快车道 | 🚶 标准 | 🐢 重型
```

### SIZE 粗判（Phase 6 任务拆解会再精算工时）

| 档 | 判据 | 预估 |
|---|---|---|
| **XS** | 单文件 / 单函数 / 纯文案 / 纯样式改动 | < 1h |
| **S** | 单模块，无新数据模型、无新外部依赖 | < 4h |
| **M** | 多模块 / 新数据模型 / 新接口 / 新依赖 | 4–8h |
| **L** | 跨系统 / 架构改动 / breaking change / 数据迁移 | > 8h |

### RISK 命中清单（出现任一关键词即 `Risk=✅`）

> 命中即"正确性/安全代价高"，**不是**"工作量大"。

- **钱**：金额 / 金钱 / 分 / cents / 取整 / rounding / 汇率 / 利息 / 计费 / billing / 支付 / payment / 退款 / refund / 结算 / settlement / 对账 / 优惠 / 税
- **数据完整性**：库存 / inventory / 配额 / quota / 幂等 / idempotent / 事务 / transaction / 数据迁移 / migration / 批量删除
- **并发**：并发 / concurrency / 锁 / 竞态 / race / 定时 / cron / 时区 / timezone / 时间戳
- **安全**：认证 / auth / 登录 / login / 密码 / password / token / 密钥 / key / 加密 / crypto / 权限 / permission / 越权 / IDOR / 注入 / injection
- **多主体访问**：分享 / 协作 / share / collaborate / 多人编辑 / 邀请 / 成员 / 租户 / tenant —— **多个主体读写同一份资源**即引入越权/隔离面（"分享一个清单"看着小，实为 RISK=✅）
- **合规/隐私**：隐私 / PII / 医疗 / 法律 / 合规 / compliance / 审计

判定**就低不就高**有疑则归入风险（漏判风险的代价远大于多跑一轮 GAN）。

### 高危子类（RISK=✅ 里**唯一**会触发 upfront 反问的窄集）

`RISK=✅` 本身**不反问** —— 它走 🏃 风险快车道，静默直跑 + 强制内联 GAN 兜底。**只有**同时满足下列任一**高危**判据，才在 Step 0 弹一次 AskUserQuestion 确认范围/lane：

| 高危判据 | 是 | 不是（仍属普通 RISK=✅，静默直跑）|
|---|---|---|
| **真实资金流转** | 真发起转账/扣款/退款/对接支付网关 | 纯前端/本地的金额计算、分摊、报表 |
| **销毁既有数据** | 批量删除/不可逆迁移**线上既有数据** | 新建数据、改本地 localStorage、可回滚变更 |
| **改动认证授权边界** | 改登录/鉴权/权限模型/密钥管理 | 读已登录态、纯展示、无鉴权的小工具 |

**判据线**：是否触及**真实资金流转 / 既有数据销毁 / 认证授权边界**。一句话——`RISK=✅` 决定"**保 GAN**"，`高危子类` 才决定"**反问 PM**"，两者不是一回事。**严禁把任意"碰钱/碰数据"笼统升级成反问**，否则刚省掉的 0-提问体验又被加回来（回归实测点名的 G2 反模式）。

## 路由矩阵

| Lane | 触发 | 跑什么 | 砍什么 | 关卡 | GAN |
|---|---|---|---|---|---|
| 🏃 **快车道** | XS/S **且** Risk=⚪ | 💬 需求澄清(轻) → 📚 直接出 INDEX+RULES（合并 PRD 要点）→ ⌨️ 代码实施 → 🛡️ 上线前检查(L1 契约 + L3 静态 + L4 运行时) → 🚀 发版 | 👥 用户研究 / 💡 方案发散 / 📐 ADR / 厚 PRD+docx | **2 个 PM 关卡默认静默自动 ✅**（PM 可在启动时说"我要看 PRD 关卡"打开）| **默认关** |
| 🏃+🛡️ **风险快车道** | XS/S **且** Risk=✅ | 同快车道，**但**：在 ⌨️ 代码实施时对**风险点代码强制内联 GAN（round-1）**；🛡️ 上线前检查**加 L2 红线编号** | 同上 | 同上 | **强制内联 round-1**；FAIL/PIVOT → 升级多轮 spawn GAN |
| 🚶 **标准** | M（任意 Risk）| 完整 17 phase | 不砍 | 2 个 PM 关卡正常 | **开**；N 自适应：Risk=✅ → N=5，Risk=⚪ → N=2–3 |
| 🐢 **重型** | L（任意 Risk）| 17 phase + 跨夜分批 | 不砍 | 2 个 PM 关卡 + batch 间断点 | **开** N=5；12.5 强制真人用户验收角色 |

**一句话记忆**：`深度 = f(SIZE)`，`是否跑 GAN/红线 = f(RISK)`。两者正交，别用 SIZE 去关 GAN。

## 🏃 快车道流程细节

PRD ⛳ 与 ☀️ 早晨复盘在快车道下**默认静默自动通过**（决策仍写 `autonomous-decisions.md` 留痕），让"一句话需求 → 直接出可跑代码"成为默认体验。

1. **💬 需求澄清（轻）**：1-2 句结构化复述 + 列关键假设（Karpathy Think Before Coding）。不写 10 段 PRD、不出 docx。
2. **📚 INDEX + RULES**：把需求要点 + 验收标准 + 技术约束直接压成 `INDEX.md`(<100 行) + `RULES.md`(<80 行)，作为实施唯一上下文（"地图不是摘要"）。
3. **⌨️ 代码实施**：按 INDEX/RULES 实现。**若 Risk=✅** → 对风险点（金额计算 / 结算 / 认证 / 并发等）跑内联 round-1 GAN（独立怀疑视角自审风险点，按 `gan-engine/reviewer-skeptical.md`），FAIL/PIVOT 才升级多轮。
4. **🛡️ 上线前检查**：L1 契约 + L3 静态 + L4 运行时（Risk=✅ 再加 L2 红线编号）。其余三层（用户研究类 L5 acceptance）按需。
5. **🚀 发版**。

**🏃 快车道极简 vault 布局**（不套用完整 17-phase 目录树，避免命名各跑各的）：
```
iteration-vault/<YYYY-MM-DD>-<short-title>/
├── 00-intake.md              # 复述 + Size/Risk/Lane 判定
├── INDEX.md + RULES.md       # 需求要点 + 约束（代替厚 PRD）
├── autonomous-decisions.md   # 静默关卡 + 自治决策留痕
├── <风险快车道才有> NN-<风险点>-gan/round-1/scorecard.md   # 如 04-money-gan/
└── 10-verification-report.md (+ Risk=✅ 时 10-verification-redlines.md)
```
其余 phase 文件（01.5/02.5/03/04/05/06/08/09/11/11.5/12 等）快车道**不产出**。

**升级闸（触发条件）**：快车道执行中若出现以下任一，**自动升级到标准 lane**——
- 实际改动超出 S（冒出新数据模型 / 跨模块 / 新依赖）
- 触发任一红线 R1–R4
- 风险快车道的 round-1 GAN 判 FAIL 且 PIVOT 仍不过

触发后按下面的「升级回流表」补跑，**不是从头重来**。

## 🔁 升级回流表（升级后怎么补跑——唯一权威清单）

> 这是「🏃 砍了什么 / 升级后补什么」的**单一权威来源**；路由矩阵"砍什么"列只是摘要，以本表为准。

**🏃 快车道实际产出（升级时已有的资产，复用不丢弃）**：`00-intake.md` + `INDEX.md`/`RULES.md` + 已写代码（视为 prototype/spike）+ 风险点 GAN scorecard（如有）。

**🏃 快车道跳过、升级后需补跑的 phase（按依赖顺序）**：

| 顺序 | 补跑 phase | 怎么复用已有资产 |
|---|---|---|
| 1 | 📝 **02 PRD（⛳ 关卡 1 恢复）** | 把轻澄清 + INDEX 扩成正式 PRD；**关卡 1 此前被静默跳过，须回头补做**（让 PM 现在看 PRD）|
| 2 | 👥 01.5 用户研究（user-facing 才需）| 轻假设型即可，标"待 12.5 真人验证" |
| 3 | 💡 02.5 方案发散 | 对已写 prototype 做事后发散，确认当前实现是不是最优解 |
| 4 | 📐 03 影响面 + ADR | **已写代码当作 spike**，倒推影响面 + 把关键技术选择补成 ADR |
| 5 | 🏗️ 04 架构 + API | 把 prototype 反向文档化成正式架构，补全数据模型/接口契约 |
| 6 | 🎨 05 界面设计 | 把快车道的简易界面补成正式 UX/UI spec（三态等）|
| 7 | 📚 05.9 重压缩 | 用补全后的设计**重新生成 INDEX/RULES**（已写代码作为约束输入）|
| 8 | 📋 06 任务拆解 | 对"prototype → 正式实现"的差量拆任务 |

**续跑起点**：补跑完 1–8 后，回到标准 lane 的 **⌨️ 07 代码实施**（在 prototype 上重构/扩展，而非重写），然后照常 08 → 09 → 10 → 11 → 11.5 → 12 → 12.5。

**关卡**：升级后 **2 个 PM 关卡恢复**（不再静默）——⛳ 关卡 1 PRD 在步骤 1 补做，⛳ 关卡 2 早晨复盘照常在 12.5。GAN 按升级后的 RISK 重新定档（碰风险面 → N=5）。

**原则**：升级 = **在已有 prototype 上补设计、补关卡、补审查**，复用而非推倒。

## 与红线 / 关卡的关系

- **红线 escalation（R1–R4）在所有 lane 始终生效** —— 快车道不豁免红线。
- **PM 关卡在快车道默认静默**，但 PM 可在 Step 0 显式要求打开（"这次我要看 PRD"）。
- 详见 `gates.md` 的"快车道下的关卡行为"段。

## 维护备忘

- 新增高风险领域（如 区块链 / 实时音视频）→ 往 RISK 命中清单补关键词。
- 若发现快车道漏跑了某个该跑的检查，多半是 SIZE 判小了或 RISK 漏判 → 调判据，**优先调 RISK 判据**（宁可多跑 GAN）。
